# Meadow: where the domain facts live

> Where the articles and the red flag rules live, who edits them, and how they
> become code.

Example only, from an invented project.

The articles, the age bands they apply to, and the red flag symptoms that send a
parent to a doctor all live in one spreadsheet. A midwife edits it. A script
turns it into code.

## The source file

`content/articles.csv`, with one row per article.

| id | title | age_band | category | red_flag | body_file |
| --- | --- | --- | --- | --- | --- |
| 0142 | Fever in the first three months | 0-3m | illness | yes | body/0142.md |
| 0143 | Fever in a toddler | 1-3y | illness | no | body/0143.md |

## The generated file

`src/data/articles.ts`. Generated by `npm run build:content`. Never edit it by
hand, and never edit both files. The generator overwrites it completely, so a
hand edit disappears the next time anybody builds.

The build fails when a row has an age band that is not in the list, a body file
that does not exist, or a red flag article with no doctor advice in the body.
Failing the build is the point, because a malformed row would otherwise ship as
a blank screen.

## Why it is set up this way

The midwife who writes the content does not read code, and she is the only
person qualified to say which symptoms are red flags. She edits a spreadsheet
and opens a pull request from the web interface. The diff shows one changed row
in a table, which she can check herself.

An agent can change an article's category and rebuild without touching any code,
and the change is reviewable by the person who is responsible for it.
